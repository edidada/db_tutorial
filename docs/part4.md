我们已经能够向数据库插入行并打印出所有行了。让我们花点时间测试一下目前为止的成果。

我打算使用 [rspec](http://rspec.info/) 来写测试，因为我对它很熟悉，而且它的语法相当易读。

我会定义一个简短的辅助方法，把一组命令发送给数据库程序，然后对输出做断言：

```ruby
describe 'database' do
  def run_script(commands)
    raw_output = nil
    IO.popen("./db", "r+") do |pipe|
      commands.each do |command|
        pipe.puts command
      end

      pipe.close_write

      # Read entire output
      raw_output = pipe.gets(nil)
    end
    raw_output.split("\n")
  end

  it 'inserts and retrieves a row' do
    result = run_script([
      "insert 1 user1 person1@example.com",
      "select",
      ".exit",
    ])
    expect(result).to match_array([
      "db > Executed.",
      "db > (1, user1, person1@example.com)",
      "Executed.",
      "db > ",
    ])
  end
end
```

这个简单的测试确保我们取回的数据和存入的数据一致。而且它通过了：
```command-line
bundle exec rspec
.

Finished in 0.00871 seconds (files took 0.09506 seconds to load)
1 example, 0 failures
```

现在测试向数据库中插入大量行是可行的：

```ruby
end
```

通读目前的代码，我意识到我们可能没有正确处理文本字段的存储。用下面这个例子很容易测试：
```ruby
it 'allows inserting strings that are the maximum length' do
  long_username = "a"*32
  long_email = "a"*255
  script = [
    "insert 1 #{long_username} #{long_email}",
    "select",
    ".exit",
  ]
  result = run_script(script)
  expect(result).to match_array([
    "db > Executed.",
    "db > (1, #{long_username}, #{long_email})",
    "Executed.",
    "db > ",
  ])
end
```

如果我们自己试一下，会看到打印这一行时出现了一些奇怪的字符。（这里把长字符串省略了）：
```command-line
db > insert 1 aaaaa... aaaaa...
Executed.
db > select
(1, aaaaa...aaa\�, aaaaa...aaa\�)
```

这是怎么回事？看一下我们对 Row 的定义，我们为 username 恰好分配了 32 字节，为 email 恰好分配了 255 字节。但 [C 字符串](http://www.cprogramming.com/tutorial/c/lesson9.html)应该以空字符结尾，而我们没有为它分配空间。解决办法是多分配一个字节：
```diff
 const uint32_t COLUMN_EMAIL_SIZE = 255;
 typedef struct {
   uint32_t id;
-  char username[COLUMN_USERNAME_SIZE];
-  char email[COLUMN_EMAIL_SIZE];
+  char username[COLUMN_USERNAME_SIZE + 1];
+  char email[COLUMN_EMAIL_SIZE + 1];
 } Row;
 ```

 这样确实修好了：
 ```ruby
 bundle exec rspec
...

Finished in 0.0188 seconds (files took 0.08516 seconds to load)
3 examples, 0 failures
```

我们不应该允许插入超过列长度的 username 或 email。相应的规格（spec）如下：
```ruby
it 'prints error message if strings are too long' do
  long_username = "a"*33
  long_email = "a"*256
  script = [
    "insert 1 #{long_username} #{long_email}",
    "select",
    ".exit",
  ]
  result = run_script(script)
  expect(result).to match_array([
    "db > String is too long.",
    "db > Executed.",
    "db > ",
  ])
end
```

为了实现这一点，我们需要升级解析器。提醒一下，我们目前使用的是 [scanf()](https://linux.die.net/man/3/scanf)：
```c
if (strncmp(input_buffer->buffer, "insert", 6) == 0) {
  statement->type = STATEMENT_INSERT;
  int args_assigned = sscanf(
      input_buffer->buffer, "insert %d %s %s", &(statement->row_to_insert.id),
      statement->row_to_insert.username, statement->row_to_insert.email);
  if (args_assigned < 3) {
    return PREPARE_SYNTAX_ERROR;
  }
  return PREPARE_SUCCESS;
}
```

但 [scanf 有一些缺点](https://stackoverflow.com/questions/2430303/disadvantages-of-scanf)。如果它读取的字符串大于目标缓冲区，就会导致缓冲区溢出，开始写入意料之外的位置。我们希望在把每个字符串复制进 `Row` 结构之前检查它的长度。要做到这一点，我们需要按空格切分输入。

我打算用 [strtok()](http://www.cplusplus.com/reference/cstring/strtok/) 来做这件事。我觉得看实际代码最容易理解：

对输入缓冲区连续调用 `strtok` 会把它切成多个子串，做法是在遇到分隔符（在我们的例子中是空格）时插入一个空字符。它返回一个指向子串开头的指针。

我们可以对每个文本值调用 [strlen()](http://www.cplusplus.com/reference/cstring/strlen/) 来判断它是否过长。

我们可以像处理其他错误码一样处理这个错误：
```diff
 enum PrepareResult_t {
   PREPARE_SUCCESS,
+  PREPARE_STRING_TOO_LONG,
   PREPARE_SYNTAX_ERROR,
   PREPARE_UNRECOGNIZED_STATEMENT
 };
```
```diff

+    continue;

     printf("Syntax error. Could not parse statement.\n");
     continue;
```
