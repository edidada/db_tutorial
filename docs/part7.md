B 树是 SQLite 用来表示表和索引的数据结构，所以它是一个非常核心的概念。本文只介绍这个数据结构，不会包含任何代码。

为什么说树是数据库适用的数据结构？

- 查找某个特定值很快（对数时间）
- 插入／删除一个已经找到的值很快（重新平衡的时间接近常数）
- 遍历一个范围内的值很快（不像哈希表那样）

B 树不同于二叉树（“B”大概代表发明者的名字，但也可能代表“平衡 balanced”）。下面是一个 B 树的例子：

{% include image.html url="assets/images/B-tree.png" description="B 树示例（https://en.wikipedia.org/wiki/File:B-tree.svg）" %}

与二叉树不同，B 树中的每个节点可以有超过 2 个子节点。每个节点最多可以有 m 个子节点，其中 m 称为树的“阶（order）”。为了让树基本保持平衡，我们还要求节点至少有 m/2 个子节点（向上取整）。

例外情况：
- 叶子节点有 0 个子节点
- 根节点可以少于 m 个子节点，但必须至少有 2 个
- 如果根节点是叶子节点（唯一的节点），它仍然有 0 个子节点

上面那张图是 B 树，SQLite 用它来存储索引。为了存储表，SQLite 使用了一种变体，叫做 B+ 树。

|                               | B 树           | B+ 树             |
|-------------------------------|----------------|-------------------|
| 读作                          | “Bee Tree”     | “Bee Plus Tree”   |
| 用于存储                      | 索引           | 表                |
| 内部节点存储键                | 是             | 是                |
| 内部节点存储值                | 是             | 否                |
| 每个节点的子节点数            | 较少           | 较多              |
| 内部节点与叶子节点            | 结构相同       | 结构不同          |

在我们实现索引之前，我只讨论 B+ 树，但我会直接把它叫做 B 树或 btree。

拥有子节点的节点称为“内部（internal）”节点。内部节点和叶子节点的结构不同：

| 对于 m 阶的树……    | 内部节点                     | 叶子节点           |
|------------------------|-------------------------------|---------------------|
| 存储                   | 键和指向子节点的指针          | 键和值              |
| 键的数量               | 最多 m-1                      | 尽量多，能放下就行  |
| 指针的数量             | 键的数量 + 1                  | 无                  |
| 值的数量               | 无                            | 键的数量            |
| 键的用途               | 用于路由                      | 与值配对            |
| 是否存储值？           | 否                            | 是                  |

我们来看一个例子，看看往 B 树中插入元素时它是如何生长的。为了简单起见，这棵树的阶为 3。这意味着：

- 每个内部节点最多 3 个子节点
- 每个内部节点最多 2 个键
- 每个内部节点至少 2 个子节点
- 每个内部节点至少 1 个键

一棵空的 B 树只有一个节点：根节点。根节点最初是一个叶子节点，有零个键／值对：

{% include image.html url="assets/images/btree1.png" description="空的 btree" %}

如果我们插入几个键／值对，它们会按排序顺序存储在叶子节点中。

{% include image.html url="assets/images/btree2.png" description="单节点 btree" %}

假设一个叶子节点的容量是两个键／值对。当我们再插入一个时，就必须拆分叶子节点，把这些对分一半放到每个节点中。这两个节点都成为一个新的内部节点的子节点，而这个内部节点现在成了根节点。

{% include image.html url="assets/images/btree3.png" description="两层 btree" %}

这个内部节点有 1 个键和 2 个指向子节点的指针。如果我们要查找一个小于或等于 5 的键，就去左边的子节点找。如果我们要查找一个大于 5 的键，就去右边的子节点找。

现在让我们插入键 "2"。首先我们查找如果它存在的话会落在哪个叶子节点，结果到达左边的叶子节点。这个节点满了，所以我们拆分叶子节点，并在父节点中创建一个新条目。

{% include image.html url="assets/images/btree4.png" description="四节点 btree" %}

让我们继续添加键。18 和 21。这时我们又一次需要拆分，但父节点里已经没有空间再放一个键／指针对了。

{% include image.html url="assets/images/btree5.png" description="内部节点没有空间了" %}

解决办法是把根节点拆分成两个内部节点，然后创建一个新的根节点作为它们的父节点。

{% include image.html url="assets/images/btree6.png" description="三层 btree" %}

树的深度只有在拆分根节点时才会增加。每个叶子节点的深度相同，键／值对的数量也接近相同，所以树保持平衡，查找也很快。

关于从树中删除键的讨论，我会推迟到实现插入之后再讲。

当我们实现这个数据结构时，每个节点将对应一个页。根节点存在于第 0 页。子指针就是包含子节点的页号。
